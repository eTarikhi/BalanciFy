Software foundations; product proof still ahead

The project has implemented substantial first-party Rust control, tunnel, crypto, service and lab tooling. CI validates software behavior and supply-chain checks; it does not establish driver runtime, live network performance, HVCI, installer readiness or field stability.

Implemented foundations

Flow scheduling and affinity, link health, capacity/congestion models, pacing/DRR, authenticated tunnel framing, replay protection, per-flow repair, key management, lab relay, IPC v1, installer journal logic, bounded raw-IP ingress and an opt-in Windows injection adapter source path.

Critical gaps

WDK build/link and static artifact checks pass, but driver artifacts are unsigned and have not been installed or run. Service IPC still uses loopback TCP and uplinks are simulated; the optional injection path is unvalidated, reverse miniport TX is absent, and production named-pipe authentication and WinUI 3/.NET GUI are missing. No real netem, Rig B, HVCI/HLK, clean-machine install or reviewed VEX evidence exists.

Dependency-gated roadmap

First close the Windows integration gate, then measure the driver, then complete product acceptance. The blueprint's 47–58 week schedule is an estimate for a 5–6 engineer team, not a current forecast.

Next: G2
