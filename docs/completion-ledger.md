## Evidence classes

- **Source** — implementation or static source-contract inspection only.
- **Unit/CI** — automated tests/builds, including hosted runner evidence; not runtime product acceptance unless the test actually runs the product in the target environment.
- **VM/lab** — signed/installed product executed in a controlled Windows VM or isolated test rig.
- **Hardware** — measurements on the specified real links/hardware.
- **External** — signing/certification/independent review or field operation evidence.
- **Blocked** — requires access, equipment, identities, or external approval unavailable in this workspace.

## Evidence collection rules

1. Record commit SHA, command, exact result, and the evidence class for every claimed pass.
2. Keep test output/logs under ignored `target/` unless a small stable report is intentionally versioned; do not add generated binaries or machine-specific datasets to Git.
3. Before moving a gate, cite actual runtime/rig results with Windows build, hardware, driver, relay and test repetitions as specified by the blueprint.
4. If tooling/equipment is absent, retain the blocker and continue independent software work; never translate a compile, simulator, dry-run, or source check into VM/hardware evidence.
